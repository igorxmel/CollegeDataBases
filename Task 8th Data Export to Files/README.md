# Практическая работа №8. Экспорт данных базы в документы пользователя

Две выгрузки из базы `torgash_Холкин` в файлы: таблица заказов в `.xlsx` и таблица
заказчиков юр.лиц в `.txt`. Выгрузка делается оператором `SELECT ... INTO OUTFILE`.

```
Solution/

    zakazy.xlsx            результат первого запроса
    zakazchiki_yur.txt     результат второго запроса
    Отчёт по ПР №8.docx    отчёт
```

Методичка про отчёт ничего не говорит, но у остальных работ курса он есть, поэтому
отчёт сделан и здесь: текст задания и запрос. Девятая работа целиком включает эти же две
выгрузки, так что файлы и запросы повторяются и там.

## Как запустить

База и Adminer поднимаются из корня репозитория:

```bash
docker compose up -d
```

Дальше http://localhost:8080, сервер `db`, пользователь `root`, пароль `root`, база
`torgash_Холкин`. Запросы из `8_export.sql` выполняются во вкладке SQL, по одному.

Выгруженные файлы появляются в папке `exchange` рядом с `docker-compose.yml`. Сервер
пишет их в свой каталог `/var/lib/mysql-files`, а Docker пробрасывает его на хост именно
в эту папку, поэтому вытаскивать файлы из контейнера не нужно.

Если контейнер был поднят до появления этой папки, его надо пересобрать, иначе файлы
останутся внутри контейнера:

```bash
docker compose down -v
```

```bash
docker compose up -d
```

Повторный запуск экспорта сначала требует удалить старые файлы, причина в разделе про
грабли.

## Разбор запросов

Оба запроса записаны по образцу из методички:

```sql
SELECT * FROM orders
INTO OUTFILE '/var/lib/mysql-files/zakazy.csv'
CHARACTER SET cp1251
FIELDS TERMINATED BY ';'
ENCLOSED BY '"'
LINES TERMINATED BY '\n';
```

От образца отличаются две вещи: путь и `CHARACTER SET cp1251`. Путь другой, потому что
MySQL пишет файлы только в каталог из `secure_file_priv`, а в Docker это
`/var/lib/mysql-files`, а не `c:/ospanel/userdata/...` из примера. Кодировка задана явно по
причине, которая описана ниже.

**Заказы в .xlsx.** Оператор не умеет писать книги Excel, он пишет текст. Поэтому запрос
выгружает `zakazy.csv`, файл открывается в Excel и сохраняется как `.xlsx`. Готовый
`zakazy.xlsx` собран так же: 21 заказ, числа и даты в нём настоящие, а не текст.

**Заказчики юр.лица в .txt.** Здесь преобразование не нужно, запрос сразу пишет
`zakazchiki_yur.txt`. В нём 7 строк, по одной на заказчика.

Заголовков столбцов в выгрузке нет: `INTO OUTFILE` пишет только строки таблицы. Значения
`NULL` он помечает как `\N`, и в заказах такая пометка стоит в каждой строке, потому что у
заказа заполнен либо номер физ.лица, либо юр.лица, а второй пустой. В `.xlsx` эти места
оставлены пустыми ячейками.

## Грабли

**Повторный запуск падает с ошибкой 1086.** `INTO OUTFILE` не перезаписывает файл, при
наличии одноимённого он отвечает `File already exists`. Перед повторной выгрузкой нужно
удалить `zakazy.csv` и `zakazchiki_yur.txt` из папки `exchange`. Именно поэтому эти два
файла добавлены в `.gitignore`: закоммиченные, они ломали бы каждый запуск на чистом
клоне.

**Без `CHARACTER SET cp1251` в Excel мусор.** Без этого предложения MySQL пишет файл в
UTF-8 без BOM. Русский Excel читает такой файл как cp1251, и «Алые паруса» превращаются в
«РђР»С‹Рµ РїР°СЂСѓСЃР°». Это проверено на настоящем Excel. С явной кодировкой файл
открывается нормально.

**Переименовать .csv в .xlsx нельзя.** Это самый короткий путь и самый частый, и он не
работает: Excel отказывается открывать такой файл, потому что формат содержимого не
совпадает с расширением. Проверено так же.

**Путь из примера в методичке в Docker не существует.** Если в запросе остался
`c:/ospanel/...`, сервер отвечает ошибкой 1290 про параметр `--secure-file-priv`, потому
что пишет только в свой разрешённый каталог. Узнать его можно запросом
`SHOW VARIABLES LIKE 'secure_file_priv'`.
