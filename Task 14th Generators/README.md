## Как запустить

Работа сдаётся на колледжном ПК через Open Server Panel и phpMyAdmin. Выбрать базу `torgash_Холкин`, на вкладке SQL (не «Импорт») вставить `14_generators.sql` и выполнить: в нём `DELIMITER`. Скрипт перезапускаемый, таблица генераторов создаётся заново.

Методичка просит в отчёте скриншот ответа для каждого генератора. В отчёте под каждым генератором оставлено место, скриншоты из phpMyAdmin вставляются руками после выполнения запроса `SELECT gen_id(...)`.

## Что решено за методичку

Методичка описывает генераторы Firebird и InterBase: `CREATE GENERATOR`, `GEN_ID`, `SET GENERATOR`. В MySQL их нет, и я сделал то же по смыслу.

| В методичке | Здесь |
| --- | --- |
| `CREATE GENERATOR GEN_ORDERS` | строка в таблице `generators` |
| `SELECT GEN_ID(GEN_ORDERS, 1)` | `SELECT gen_id('GEN_ORDERS', 1)`, функция |
| `GEN_ID(..., 0)` | `gen_id('GEN_ORDERS', 0)` возвращает текущее значение |
| `SET GENERATOR ... TO значение` | `CALL set_generator('GEN_DOC_NO', 1000)` |
| `DROP GENERATOR` | `DELETE FROM generators WHERE name = ...` |

Альтернатива, `CREATE SEQUENCE` и `NEXTVAL`, есть только в MariaDB 10.3 и новее и в MySQL не работает, поэтому выбрана таблица, которая работает в обоих.

## Разбор

**Функция.** `gen_id` прибавляет шаг к значению и возвращает новое, а если генератора нет, отвечает ошибкой:

```sql
UPDATE generators SET value = LAST_INSERT_ID(value + inc) WHERE name = gen_name;
RETURN LAST_INSERT_ID();
```

`LAST_INSERT_ID(выражение)` запоминает значение для текущего соединения, поэтому два пользователя, обратившиеся одновременно, не получат одно и то же число.

**Генераторы.** `GEN_ORDERS` и `GEN_CUSTOMERS_FIZ` стартуют с наибольшего номера в своих таблицах, то есть продолжают существующую нумерацию. `GEN_DOC_NO` стартует с 1000 и растёт с шагом 10, шаг передаётся прямо в `gen_id`.

**Главное свойство.** Значение генератора не откатывается вместе с транзакцией. Это проверено: заказ вставляется в транзакции с номером из генератора и откатывается, а следующий вызов `gen_id('GEN_ORDERS', 0)` показывает уже увеличенное число. Заказа в таблице нет, а номер использован.

## Грабли

**MyISAM нужен намеренно.** Таблица `generators` создана с движком MyISAM, у которого нет транзакций. В InnoDB счётчик откатился бы вместе с транзакцией, и главное свойство генератора пропало бы.

**Ошибка 1418 при создании функции.** Если на сервере включён бинарный журнал (в MySQL 8 он включён по умолчанию), он не разрешает функции, которые меняют данные: `This function has none of DETERMINISTIC, NO SQL, or READS SQL DATA`. В начале скрипта стоит `SET GLOBAL log_bin_trust_function_creators = 1`, которая снимает ограничение. Нужны права root. Без бинарного журнала она ничего не меняет.

**Генераторы не заменяют `AUTO_INCREMENT`.** Ключи в таблицах остаются автоматическими. Генератор только выдаёт число, а вставлять ли его в ключ, решает запрос: `VALUES (gen_id('GEN_ORDERS', 1), ...)`.
