## Как запустить

Работа сдаётся на колледжном ПК через Open Server Panel и phpMyAdmin. Выбрать базу `torgash_Холкин`, на вкладке SQL (не «Импорт») вставить `12_procedures.sql` и выполнить. Скрипт перезапускаемый, каждая процедура перед созданием удаляется. В конце стоят вызовы всех процедур: phpMyAdmin показывает результат каждого `SELECT` отдельной таблицей.

Методичка в конце просит сохранить результат запроса в представление. К процедурам это относится слабо, поэтому в представление `v12_pr2` сохранён только запрос из `Pr2`, единственный, который выдаёт один готовый результат.

## Разбор процедур

**Pr1.** Характеристики из задания идут между заголовком и телом: `LANGUAGE sql DETERMINISTIC SQL SECURITY DEFINER COMMENT 'First'`. Тело выводит надпись.

**show_all.** Методичка просит вывести все таблицы базы. Список таблиц процедура берёт из `information_schema.tables` курсором и для каждой собирает запрос строкой и выполняет через `PREPARE`. Так она работает, даже если в базе есть таблицы других работ (`postavki`, `vozvraty`) или каких-то из них нет, и не придётся править при появлении новой таблицы.

**Pr2.** Считает заказы заказчиков физ.лиц из Казани мужского пола через соединение `orders` и `customers_fiz`. В данных их два, оба у Астахова.

**Pr3.** Входной `num1 INT`, выходной `num2 DOUBLE`, значение `EXP(num1)`. Вызов: `CALL Pr3(2, @num2); SELECT @num2;` даёт 7.38905609893065.

**Pr4.** Принимает строку, объявляет `X INT`, ставит 1 для `North` и 0 для остальных и выводит `X`. Имя переменной записано латинской X.

**Pr5.** Цикл `WHILE` от 1 до n, в каждом проходе `IF i MOD 2 = 0 OR i MOD 3 = 0` и `SELECT i`. Для n = 10 выводит 2, 3, 4, 6, 8, 9, 10, каждое отдельной таблицей, как в примере методички.

**Pr6.** Курсор по `SELECT amt FROM orders WHERE amt > 999`, обработчик `NOT FOUND` ставит признак конца, сумма копится в выходном параметре. Для всех заказов результат 109831.13.

## Теоретическая часть

Хранимая процедура это именованный набор операторов, который хранится на сервере и вызывается командой `CALL`. Она может принимать входные (`IN`), выходные (`OUT`) и двунаправленные (`INOUT`) параметры. Внутри доступны переменные, ветвления, циклы, курсоры и обработчики ошибок. Тело содержит точки с запятой, поэтому на время создания меняется разделитель командой `DELIMITER`.

## Ответы на вопросы

**1. В чём преимущества и недостатки хранимых процедур?** Процедура хранится и выполняется на сервере, поэтому по сети не гоняется текст запросов, а готовый план можно использовать повторно. Одну логику пишут один раз и вызывают из разных приложений, а права можно выдать на процедуру, не открывая таблицы. Недостатки: логика оказывается внутри базы, где хуже версионирование и отладка, нагрузка ложится на сервер СУБД, а синтаксис привязан к конкретной СУБД и плохо переносится.

**2. Объясните назначение оператора DELIMITER.** Клиент считает концом команды символ `;`, но он же стоит внутри тела процедуры между её операторами. `DELIMITER` временно задаёт другой символ окончания команды, например `$$`, и тело процедуры уходит на сервер целиком. После создания разделитель возвращается командой `DELIMITER ;`.

**3. Как вызвать процедуру с выходным параметром и что такое системные переменные?** Процедура вызывается командой `CALL`, а в качестве выходного параметра передаётся переменная сеанса: `CALL Pr3(2, @num2);`, затем значение читается запросом `SELECT @num2;`. Переменные с одной `@` создаёт пользователь, они живут до конца соединения. Системные переменные с двумя `@@` принадлежат серверу и хранят его настройки, например `@@version` или `@@secure_file_priv`.

**4. Какие операторы программирования в хранимых процедурах вы знаете?** Объявление и присваивание: `DECLARE`, `SET`. Ветвления: `IF ... THEN ... ELSE` и `CASE`. Циклы: `WHILE`, `REPEAT` и `LOOP` с операторами `LEAVE` и `ITERATE`. Работа с курсором: `DECLARE CURSOR`, `OPEN`, `FETCH`, `CLOSE` и обработчик `DECLARE HANDLER`. Вызов другой процедуры: `CALL`.

**5. Зачем нужны курсоры?** Курсор позволяет пройти по строкам результата запроса одну за другой и обработать каждую внутри процедуры, например собрать сумму. Он доступен только для чтения, идёт только вперёд и не отражает изменений таблицы, которые произошли после его открытия.

## Грабли

**Курсор и `NOT FOUND`.** Обработчик объявляется после курсора и ставит признак, а проверять его нужно сразу после `FETCH`. В примере методички проверка стоит после присваивания в цикле `WHILE`, и если забыть `IF`, последняя строка посчитается дважды. В `Pr6` цикл `LOOP` с `LEAVE` выходит сразу.
