# College Data Bases

Практические работы по базам данных. Здесь лежат мои решения.

Каждое задание живёт в отдельной папке. Внутри исходная методичка и папка `Solution`
с файлами решения. Начиная с пятой работы рядом лежит ещё `README.md` с разбором решения
и описанием того, как его запустить. Работы под номером 1 и 4 в курсе нет, эти номера
пропущены.

## Задания

- [Task 2. Подсистема учёта материалов](Task%202nd%20Warehouse%20and%20Materials%20Subsystem)
  Задание демонстрационного экзамена по специальности 09.02.07, вариант 1: база данных
  SQLite и десктопное приложение на Python и tkinter для компании «Мозаика». Просмотр
  списка материалов, добавление и редактирование материала, список поставщиков.

- [Task 3. Техническая документация проекта](Task%203rd%20Database%20Documentation)
  Словарь данных на базу из второй работы: описание шести связей и семи таблиц с типами,
  размерностями, ограничениями и ключами.

- [Task 5. Создание и модификация базы данных в MySQL](Task%205th%20MySQL%20Create%20and%20Modify)
  База `torgash_Холкин` из шести таблиц с ограничениями и триггерами (часть 5.1) и
  изменение структуры через ALTER TABLE с автоматическим заполнением полей (часть 5.2).

- [Task 6. Каскадные операции и ссылочная целостность](Task%206th%20Cascade%20Operations%20and%20Referential%20Integrity)
  Отдельная база `Biblioteka` из шести таблиц: семь каскадных правил на внешних ключах
  и триггер, обнуляющий ссылку на аннулированное издательство.

- [Task 7. Выборка данных и представления](Task%207th%20SELECT%20Queries%20and%20Views)
  Сорок два запроса к базе `torgash_Холкин` в четырёх частях: условия и агрегатные
  функции, группировка, соединения и подзапросы, UNION с ANY и ALL. Результат каждого
  запроса сохранён в представление.

- [Task 8. Экспорт данных в файлы](Task%208th%20Data%20Export%20to%20Files)
  Выгрузка таблицы заказов в `.xlsx` и таблицы заказчиков юр.лиц в `.txt` оператором
  `SELECT ... INTO OUTFILE`.

- [Task 9. Импорт и экспорт данных](Task%209th%20Data%20Import%20and%20Export)
  Две новые таблицы, поставки и возвраты, заполняются из `.xlsx` и `.txt` командой
  `LOAD DATA INFILE`. Экспорт тот же, что в восьмой работе.

- [Task 10. Объединение таблицы с собой](Task%2010th%20Self%20Join)
  Семь запросов с самосоединением к базе `torgash_Холкин`, результат каждого сохранён в
  представление.

## Как поднять базу

В репозитории лежит `docker-compose.yml`, который поднимает MySQL 8 и Adminer. Нужен
только Docker, ничего больше устанавливать и настраивать не надо.

```bash
docker compose up -d
```

Дальше открыть http://localhost:8080. Сервер `db`, пользователь `root`, пароль `root`.
В списке баз будут обе: `torgash_Холкин` из пятой работы и `Biblioteka` из шестой. Скрипты
выполняются при первом запуске автоматически.

Остановить: `docker compose down`. Стереть базу и собрать заново: `docker compose down -v`,
потом снова `up`. Пересборка нужна после правки скриптов, иначе изменения не подхватятся.

Почему именно MySQL, а не MariaDB из XAMPP: MariaDB не принимает кириллицу в имени базы,
а по заданию она там нужна. Заодно снимаются ещё две проблемы, `CHECK` проверяется
по-настоящему, а `CURDATE()` работает как положено.

Новая работа подключается одной строкой в `volumes` в `docker-compose.yml`, номер в имени
задаёт порядок выполнения. Базы при этом не обязаны быть одной: пятая работа идёт на
`torgash_Холкин`, шестая создаёт свою `Biblioteka`, и в одном контейнере они уживаются.

Файлы для импорта и выгрузки лежат в папке `exchange`: Docker подключает её к каталогу
`/var/lib/mysql-files`, единственному, откуда сервер читает и куда пишет файлы. Если
контейнер собран до восьмой работы, его нужно пересобрать: `docker compose down -v`, потом
`up -d`.
