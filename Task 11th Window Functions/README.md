Работа сдаётся на колледжном ПК через Open Server Panel и phpMyAdmin. Выбрать базу `torgash_Холкин`, на вкладке SQL (не «Импорт») вставить `11_window.sql` и выполнить. ## Разбор запросов

**1. Максимальная комиссия в каждом городе.** `MAX(comm) OVER (PARTITION BY city)` считает максимум по городу и приписывает его к каждой строке продавца, строки не схлопываются, как было бы при `GROUP BY`. Номер уникальности даёт `ROW_NUMBER() OVER (ORDER BY id_s)`, он стоит перед столбцом с максимумом, как просит задание.

**2. Накопительный итог.** Окно делится по продавцу и упорядочено по дате:

```sql
SUM(o.amt) OVER (PARTITION BY o.id_s ORDER BY o.odate, o.id_z)
```

Номер заказа добавлен в сортировку нарочно. Без него у двух заказов одного дня итог посчитался бы одним числом, потому что по умолчанию окно с `ORDER BY` работает в режиме `RANGE`, а он считает строки с одинаковым ключом одной. В данных такие заказы есть (у СтройМаркт два заказа 15.01.2024).

**3. Максимальный заказ физ.лица и предшествующий ему.** В общем табличном выражении заказы заказчика нумеруются по убыванию стоимости, второй по номеру и есть предшествующий максимальному. Оконный `MAX` по заказчику повторяет его в каждой строке. У заказчиков с одним заказом предшествующего нет, там `NULL`.

**4. Лидер среди юр.лиц.** Сначала сумма по каждому юр.лицу, потом `RANK() OVER (ORDER BY total DESC)` ставит места, и выбирается первое. Результат: Канцлер, 29385.38. Пункт 4.1 добавляет имя и сумму, пункт 4.2 условие `place <= 2`: на втором месте Южный ветер, 28323.50.

## Теоретическая часть

Окно это набор строк, в рамках которого считается значение. Оконная функция добавляет вычисленное значение к каждой строке и не группирует их. Окно задаётся предложением `OVER`: `PARTITION BY` делит строки на группы, `ORDER BY` упорядочивает внутри группы, `ROWS` или `RANGE` ограничивает рамку (текущая строка, все предыдущие, заданное число соседних). `ROW_NUMBER` нумерует строки, `RANK` ставит места с пропусками при равенстве, `LAG` и `LEAD` берут значение предыдущей или следующей строки. Конструкция `WITH` создаёт общее табличное выражение: временный именованный результат запроса, на который можно ссылаться ниже, в том числе несколько раз.

## Грабли

**Имя столбца длиннее 64 символов не создаётся.** Заголовок «Стоимость заказа, предшествующая максимальной для данного Заказчика физ.лица» из задания длиннее лимита MySQL, представление падает с ошибкой 1166 `Incorrect column name`. В запросе он сокращён до «Стоимость заказа, предшествующая максимальной».

**RANK и равные суммы.** Если бы у двух юр.лиц оказалась одинаковая сумма, `RANK` дал бы обоим первое место, а второго не было бы вовсе. В данных суммы разные, поэтому запрос 4.2 возвращает ровно двух.

**Представление с CTE и оконными функциями** создаётся только в MySQL 8.0 и новее.
