## Как запустить

Работа сдаётся на колледжном ПК через Open Server Panel. Консоль Open Server Panel (пункт «Консоль» в меню программы) открывает командную строку с настроенным путём к `mysqldump` и `mysql`. Перейти в папку, куда должны лечь копии, и выполнить команды из `18_backup.txt` по порядку. На запрос пароля ввести пароль `root`, в Open Server Panel он по умолчанию пустой, тогда достаточно Enter.

Методичка просит скриншоты: подробный вывод для архивной копии и наличие архивных файлов в папке для остальных. Их делает тот, кто выполняет команды, в отчёте под ними оставлены места.

## Разбор команд

**1. Обычная копия.** `mysqldump -h 127.0.0.1 -u root -p --routines torgash_Холкин > dump_Холкин.sql`. Ключ `--routines` добавлен к методичке: по умолчанию `mysqldump` не выгружает процедуры и функции, а в базе они есть из работ 12 и 14. Триггеры и представления он выгружает сам.

**2. Архивная копия с подробным выводом.** Результат идёт по конвейеру в `gzip`. Ключ `-v` печатает ход работы в поток ошибок, он остаётся на экране и в файл не попадает, поэтому скриншот выводит именно его.

**3. Таблица «Заказы».** После имени базы через пробел указывается таблица: `torgash_Холкин orders`. В копии одна таблица.

**4. Права доступа.** Учётные записи и права хранятся в служебной базе `mysql`, поэтому выгружаются её таблицы `user`, `db` и `tables_priv`: пользователи с паролями, права на базу и права на отдельные таблицы. Методичка называет только `user`, но права на таблицы из ПР №17 лежат в `tables_priv`.

**5. Без таблицы «Вид собственности».** Ключ `--ignore-table=база.таблица`, таблица называется `vids`.

**6. Восстановление.** Сначала создаётся новая база `torgash_Холкин_copy`, потом в неё загружается файл: `mysql ... torgash_Холкин_copy < dump_Холкин.sql`. В копии нет `CREATE DATABASE`, поэтому она ложится в ту базу, которая указана в команде.

## Теоретическая часть

Резервные копии бывают логические и физические. Логическая это скрипт из команд, которые создают базу и заполняют её. Она переносима на другую версию сервера, но восстановление большой базы идёт долго. Физическая это копия файлов базы: быстро, но нужна полная совместимость версий и копировать работающий сервер опасно. Логическую копию делает `mysqldump`, её лучше сразу архивировать через `gzip`: текстовые дампы сжимаются в десять раз и больше. Для восстановления из копии, которая была сделана вместе с журналом изменений, двоичные журналы сначала переводятся в SQL утилитой `mysqlbinlog`.

## Что не проверено

Команды проверены на MySQL 8.0 в Docker с теми же флагами: все пять копий создались, восстановление в новую базу вернуло 8 таблиц, 56 представлений, 7 процедур, 9 триггеров и 21 заказ с русскими данными. Запуск именно в консоли Open Server Panel я не проверял, там возможны три отличия.

**Нет `gzip`.** В обычной командной строке Windows его может не быть. Тогда копию делают без конвейера, а потом архивируют встроенной утилитой: `tar -a -c -f dump_arh_Холкин.zip dump_arh_Холкин.sql`.

**Кириллица в имени базы.** Если `mysqldump` отвечает `Unknown database` на `torgash_Холкин`, в команду добавляют `--default-character-set=cp1251` или выполняют `chcp 65001` перед ней.

**Запрос пароля.** Ключ `-p` без значения спрашивает пароль, в проверке пароль был подставлен прямо в команду.

## Грабли

**Подробный вывод не попадает в файл.** `-v` пишет в поток ошибок, а `>` и `|` перенаправляют только основной поток. Поэтому файл остаётся чистым, а на экране видно ход работы.

**`mysql` без `--default-character-set=utf8mb4`.** Клиент в контейнере по умолчанию использовал не UTF-8, и команда с кириллицей в имени базы падала с ошибкой синтаксиса. В командах восстановления ключ указан явно.
